Dreamer Studio Dreamer Package Format

Dreamer Package Format

Updated 2026-10-21Owner: architectReq: TSK-012Format version 1

Overview

A Dreamer package is a ZIP file that moves a novel and its metadata between Dreamer Studio and other tools. Import uses it in REQ-013. Export writes it in REQ-018.

  • The format is read-only during preview. Reading never writes, creates, or deletes files.
  • Version 1 supports novels.
  • All chapter text is normalized before preview, import, search, or export.

Layout

dreamer-package.zip
├── metadata.json              # required; exact name at the root
├── cover.jpg                  # optional; JPG or PNG content
├── chapters/                  # chapter files listed by metadata.json
│   ├── 0001.txt
│   └── 0002.txt
└── notes.txt                  # ignored; shown in the import preview
  • metadata.json is required at the package root.
  • A cover is optional. Its content must be JPEG or PNG.
  • Chapter files are UTF-8 text files under chapters/.
  • Other entries are ignored and shown in the import preview.

metadata.json

The file is a UTF-8 JSON object. Unknown fields do not change the normalized metadata.

FieldTypeRequiredDefaultRule
formatVersionnumberYes—Must be 1.
typestringYes—Must be novel.
originalTitlestringYes—Trimmed. Must not be empty.
titlestringNo""Trimmed.
authorstringNo""Trimmed.
descriptionstringNo""Trimmed.
tagsstring[]No[]Each tag is trimmed. Empty tags are dropped. Case-insensitive duplicates are dropped after the first value.
languagestringYes—Trimmed BCP-47 language tag. Stored in canonical form.
publicationstringNoongoingongoing or completed.
coverstring or nullNonullNames an entry whose magic bytes identify JPEG or PNG content.
chaptersarrayYes—Ordered [{ file, title }]. It may be empty. file is a string under chapters/. Optional title is trimmed and defaults to "".

Versioning and type

  • Version 1 is the only supported package version.
  • A different formatVersion is rejected with versionUnsupported.
  • A type other than novel is rejected with unsupportedType. Other content types are not supported yet.

Limits

The reader uses PACKAGE_LIMITS. A limit is inclusive. A package is refused when a value is greater than its limit.

LimitMaximumBytesApplies to
zipBytes200 MB209,715,200The ZIP file.
unpackedBytes500 MB524,288,000The sum of uncompressed entry sizes.
entries20,000—All entries in the central directory.
chapterBytes5 MB5,242,880Each chapter and metadata.json.
coverBytes10 MB10,485,760The listed cover.

Entry count and declared uncompressed sizes are checked from the ZIP central directory. Bytes are then counted again while each entry is inflated. Reading stops at the first size overflow.

Paths

The package is refused when an entry name is unsafe.

  • Absolute names that start with / are unsafe.
  • Drive-letter names such as C:/file.txt are unsafe.
  • Any path segment equal to .. is unsafe.
  • Backslashes and NUL characters are unsafe.
  • Duplicate entry names are unsafe. Comparison is case-insensitive.
  • Symlink entries are ignored. They count as absent when referenced.
  • Every listed chapter file must start with chapters/.
  • Names inside the package are never used as names in the library.

Text and paragraphs

  • Metadata and chapters use strict UTF-8. Invalid bytes reject the package. The reason names the file.
  • A leading UTF-8 byte order mark is removed.
  • CRLF and lone CR line endings become LF.
  • Every non-empty line is one paragraph.
  • Each line is trimmed. Blank and whitespace-only lines are dropped.
  • Export writes one paragraph per line with a blank line between paragraphs. Reading it produces the same paragraph list.

Import, export, chapter split, reader, and search use this one rule from shared/core/novel-text.ts. An empty chapter file and a package with zero chapters are valid.

Preview valueDefinition
paragraphsThe number of normalized non-empty lines.
charsThe number of Unicode code points in normalized text, excluding line breaks.
hashLowercase hexadecimal SHA-256 of the UTF-8 bytes of normalized text.

Checks

Refusals stop package reading at the first refusal. A problems refusal returns all problems that can be found safely. Warnings never block import.

Refusals

CodeWhenParams
notZipThe path is not an existing regular .zip file; the ZIP cannot be opened; or an entry is encrypted.{}
unsafePathAn entry name is unsafe or duplicates an earlier name case-insensitively.{ entry }
unsupportedTypemetadata.json has a type other than novel.{ type }
tooLargeThe ZIP, unpacked data, entry count, metadata, a chapter, or the cover exceeds its limit.{ limit, size, max }; chapter, metadata, and cover cases also have file.
problemsOne or more package problems were found.{ count }

Sample package

The fixture is at electron/main/features/library/fixtures/sample-novel/. Tests in package-reader.test.ts package and read this directory.

sample-novel/
├── metadata.json
├── cover.png
├── chapters/
│   ├── 0001.txt              # UTF-8 BOM, CRLF, blank and padded lines
│   ├── 0002.txt              # two paragraphs
│   ├── 0003.txt              # empty
│   └── 0004.txt              # same text as 0002.txt
└── notes.txt                 # not listed; ignored
