Dreamer Studio Ontology Format

Ontology Format

Updated 2026-10-26Owner: architectReq: REQ-030Format version 1

Overview

ontology.yml tells World Analysis (TH04-01) what to do, which entity types and which facts to extract from a novel. It is a UTF-8 YAML file at library/<novel-id>/analysis/ontology.yml.

Lifecycle

  1. The app ships a default ontology at resources/ontology.default.yml. The Omniscient page shows this default until the novel has its own file.
  2. The app copies the default to the novel on its first analysis or when the user first clicks Open in system editor. The file must exist before the editor opens.
  3. Later analyses use the novel's copy. The user edits it in the system editor, then clicks Re-check.
  4. Reset to default replaces the novel's copy after confirmation. Reset is blocked while the novel is locked.
  • The app checks the file when the Omniscient page opens, on Re-check, and before a run. There is no file watcher.
  • An invalid file blocks analysis. The page lists every problem with its line and reason.
  • Changes apply from the next analysis. Existing results do not change.

Layout

library/<novel-id>/
└── analysis/
    └── ontology.yml              # the novel's copy

The YAML root is a map with only these keys:

KeyRequiredRule
nameNoText label of the ontology.
versionYesMust be 1.
taskYesText that tells the LLM what to do. Sent at the top of every prompt.
rulesNoList of text rules, sent in every prompt.
entity_schemaYesList of entity types and their properties.
scalar_predicatesYesList of attributes of one entity. May be [].
connection_predicatesYesList of relations between two entities. May be [].

Entity schema

A novel may list fewer than the six known types. Each item has these keys:

KeyRequiredRule
typeYesOne of the known types below, listed once.
descriptionNoText that guides the LLM.
examplesNoList of example names, sent to the LLM.
propertiesYesList of the type's own properties. Must contain name.
TypeMeaning
CharacterAn abstract person. Has only a name; linked to its identities by has_persona.
PersonaOne identity of a character; carries the character's other facts.
LocationA named place or structure.
OrganizationA family, sect, kingdom, guild or faction.
ArtifactA named object, weapon, treasure, pill or material.
GlossaryAny other named thing of the world: a concept, technique, cultivation level, title or term.

Properties

Properties are part of the entity, not facts. The LLM extracts them with the entity in the candidates step.

KeyRequiredRule
propertyYesname, alias or title, listed once per type.
requiredNotrue when every entity of the type has it. Must be true for name.
multipleNotrue when the entity may have many values. Must be false for name and true for alias and title.
descriptionNoText that guides the LLM.
  • name: the entity's name. One value, required for every type.
  • alias: other names of the entity. Aliases of a type without this property are dropped.
  • title: positions or honorific titles. Titles of a type without this property are dropped.

Scalar predicates

Each item has these keys. Predicate names are unique across both lists.

KeyRequiredRule
predicateYesUnique name.
domainYesNon-empty list of entity types that may have this attribute.
descriptionNoText that guides the LLM.
  • A scalar fact has no value. It is the quote, copied from the chapter, that describes the attribute.
  • An entity may have many scalar facts of one predicate, for example one per chapter.

Connection predicates

KeyRequiredRule
predicateYesUnique name.
subjectYesNon-empty list of entity types.
objectYesNon-empty list of entity types.
symmetricNotrue when A→B also means B→A. Subject and object must list the same types. The app keeps one link per pair.
labeledNotrue when each fact needs a label that names the relation. The graph shows the label.
descriptionNoText that guides the LLM.
  • Every type in domain, subject and object must appear in entity_schema.
  • No other keys are allowed in any item.

Persona rule

  • A character is an abstract entity. It has only a name and may appear only in has_persona, which must be subject: [Character], object: [Persona] and not symmetric.
  • Every other fact belongs to a persona or another type.
  • If Character is listed, Persona and has_persona are required.
  • In the candidates step, every character needs a persona with the same name, its true self. The LLM is asked again when one is missing.

For example, the character Peter Parker has the personas "Peter Parker" and "Spider-Man". "Spider-Man member_of Avengers" is a persona fact.

Example

name: small-ontology
version: 1
task: Extract the entities and facts from the chapters.
rules:
  - Extract only facts stated explicitly in the text.
entity_schema:
  - type: Character
    properties:
      - property: name
        required: true
  - type: Persona
    examples: [Spider-Man]
    properties:
      - property: name
        required: true
      - property: alias
        multiple: true
      - property: title
        multiple: true
  - type: Organization
    properties: [{ property: name, required: true }]
scalar_predicates:
  - predicate: gender
    domain: [Persona]
connection_predicates:
  - predicate: has_persona
    subject: [Character]
    object: [Persona]
  - predicate: member_of
    subject: [Persona]
    object: [Organization]
  - predicate: other_relation
    subject: [Persona]
    object: [Persona]
    symmetric: true
    labeled: true

Default ontology

The full default file is electron/resources/ontology.default.yml. It lists all six entity types. Every type has name; only Persona has alias and title.
