Dreamer Studio Ontology Format

Ontology Format

Updated 2026-10-26Owner: architectReq: REQ-030Format version 1

Overview

ontology.yml tells World Analysis (TH04-01) which entity types and facts to extract from a novel. It is a UTF-8 YAML file at library/<novel-id>/analysis/ontology.yml.

Lifecycle

  1. The app ships a default ontology at resources/ontology.default.yml. The Omniscient page shows this default until the novel has its own file.
  2. The app copies the default to the novel on its first analysis or when the user first clicks Open in system editor. The file must exist before the editor opens.
  3. Later analyses use the novel's copy. The user edits it in the system editor, then clicks Re-check.
  4. Reset to default replaces the novel's copy after confirmation. Reset is blocked while the novel is locked.
  • The app checks the file when the Omniscient page opens, on Re-check, and before a run. There is no file watcher.
  • An invalid file blocks analysis. The page lists every problem with its line and reason.
  • Changes apply from the next analysis. Existing results do not change.

Layout

library/<novel-id>/
└── analysis/
    └── ontology.yml              # the novel's copy

The YAML root is a map with only these keys:

KeyRequiredRule
versionYesMust be 1.
entityTypesYesMap of allowed entity type names to one-line descriptions.
predicatesYesMap of unique predicate names to their fields.

Entity types

A novel may list fewer than the five allowed types. Each listed type has a one-line text description. The description is optional and may be empty; use "" for an empty value.

TypeMeaning
characterAn abstract person, linked to its identities by persona of.
personaOne identity of a character; carries the character's other facts.
locationA place in the world.
organizationA sect, clan, company, or other group.
glossaryA named thing of the world, such as a technique, item, title, or term.

Predicates

Each predicate name is unique. Its value is a map with these fields:

FieldRequiredRule
kindYesrelationship links two entities; scalar gives one entity a value.
subjectYesNon-empty list of entity types that may have this fact.
objectRelationship onlyNon-empty list of entity types that may be targets. Required for a relationship; not allowed for a scalar.
valuesNoScalar only. Non-empty list of unique allowed text values. Omit it to allow any text.
descriptionNoText that guides the LLM.
  • Every type in subject and object must appear in entityTypes.
  • No other predicate fields are allowed.

Persona rule

  • A character is an abstract entity. Its only predicate is persona of, with subject: [persona] and object: [character].
  • Every other fact belongs to a persona, location, organization, or glossary term.
  • If character is listed, persona and the persona of relationship are required.

For example, the character Peter Parker has the personas "Peter Parker" and "Spider-Man". "Spider-Man member of Avengers" is a persona fact.

Example

version: 1
entityTypes:
  character: An abstract person. Linked to its personas only by "persona of".
  persona: One identity of a character. Carries every other fact of the character.
  organization: A sect, clan, company, or other group.
predicates:
  persona of:
    kind: relationship
    subject: [persona]
    object: [character]
    description: The persona is an identity of the character.
  member of:
    kind: relationship
    subject: [persona]
    object: [organization]
  gender:
    kind: scalar
    subject: [persona]
    values: [female, male, unknown]

Default ontology

The full default file is electron/resources/ontology.default.yml. It lists all five entity types: character, persona, location, organization, and glossary.
